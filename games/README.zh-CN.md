# 游戏

一个游戏一个文件夹。不限语言，不限引擎。

当前可玩的 demo 是 [`docs/`](../docs/) 里的贪吃蛇、乒乓和记忆翻牌，因为它们同时也充当双语展示站。那只是一个例子，不是规则。下一个原型可以是 Godot 工程、Unity 场景、Pygame 脚本、LÖVE 游戏、Raylib 可执行文件、终端游戏，或者更奇怪的东西。

## 建议结构

```text
games/
└── my-game/
    ├── README.md          # 是什么、怎么运行、操作、资源署名
    ├── src/               # 源码；如果引擎有自己的目录结构就按引擎来
    ├── project.godot      # 或者 *.unity、*.uproject、main.py……
    └── assets/            # 只放这个游戏专用的资源
```

如果多个游戏共用同一个资源，请放到顶层的 [`assets/`](../assets/) 文件夹。

## 游戏 README 模板

```markdown
# 游戏名

- **状态：** 原型 / 可玩 / 暂停
- **语言：**
- **引擎 / 运行时：** 版本（如果有）
- **如何运行：**
- **操作：**
- **资源与署名：**
- **我学到了什么：**
```

## 规则

- **一个游戏一个文件夹。** 入口要明显。
- **写清工具链。** 说明语言/引擎和版本，让别人能跑起来。
- **写清启动方式。** 一条命令、一个编辑器版本，或者一个构建步骤。不假设别人已经配好环境。
- **不要把生成物提交进 Git。** 大的构建产物放 releases 或下载链接。
- **资源要署名。** 共享资源放 `../assets/`；第三方资源记到 [`../assets/CREDITS.md`](../assets/CREDITS.md) 或游戏 README。
- **做小一点。** 目标是能玩的一屏原型，不是生产管线。

不要求任何语言或引擎。唯一的要求是：别人能运行它，也能看懂它。
