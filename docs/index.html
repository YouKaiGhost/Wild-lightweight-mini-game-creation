What this is

A public notebook for lightweight game design

This repository collects small, finishable game experiments. The goal is not to ship a commercial title. The goal is to practice the whole loop: choose one mechanic, build a rough prototype, play it, write down what broke, and try again.

Everything here is intentionally modest: each demo opens as a plain HTML file, the rules fit on one screen, and the code stays short enough to read in one sitting. Future prototypes may use a different language or engine, but the same size limit applies.

01

One mechanic

Each prototype explores a single verb: move, dodge, collect, or bounce. Depth comes from constraints, not feature lists.

02

Recreate first

Rebuilding a classic is an honest way to learn. The rules are known, so the lesson is in the implementation and the feel.

03

Finish small

A prototype that ends is worth more than a masterpiece that never ships. One screen, one score, one more try.

Any stack

Any language. Any engine.

The goal is to finish a small game, not to defend a tool. Use Godot, Unity, Pygame, LÖVE, Raylib, plain web, or something else — if it helps you ship one screen, it belongs here.

The current Snake, Pong, and Memory demos are vanilla web because they run anywhere. The next prototype does not have to be.

Tiny design notes

Rules I keep relearning

Short notes from building small games. They are opinions, not laws.

01

The first 10 seconds

If a player cannot move, understand the goal, and fail once within ten seconds, the prototype is too slow.

02

Input is design

Buffering the next turn, forgiving a near miss, and showing why you died matter more than extra levels.

03

Scope is a mechanic

Every feature must earn its place on the one screen. If it needs a menu, it probably belongs in the next prototype.

04

Write down the failure

A two-line note after playtesting is worth more than a week of guessing. The log is part of the game.
